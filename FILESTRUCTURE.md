# Project File Structure

This document provides an in-depth explanation of the directory layout and the purpose of the folders within the Disaster Management Mesh Network repository.

## Root Directory (`c:\ecs2`)

- `README.md`: The universal entry point explaining the project, problem statement, and architecture.
- `FILESTRUCTURE.md`: This file, explaining the folder and file structure in detail.
- `.git/`: Git version control system directory.

---

### `/actualplan`
Contains the core theoretical and architectural design documents.
- `final_esp32_rescue_mesh_full_architecture.md`: The complete, detailed architectural specification of the ESP32 mesh network. It explains the cryptography, key architecture, the separation between Normal Nodes and Rescue Nodes, and the provisioning process.
- `mesh_rescue_architecture_complete.md`: Additional or older architectural specifications and plans for the mesh setup.

### `/backend`
The backend system built with Node.js, Express, Prisma, and PostgreSQL. It is responsible for storing and providing data APIs for the frontends.
- `src/`: Contains the TypeScript source code for the Express server and API routes.
- `prisma/`: Contains `schema.prisma`, which defines the PostgreSQL database schema for the application.
- `package.json` / `tsconfig.json`: Node dependencies, scripts, and TypeScript configuration.
- `.env` / `.env.example`: Environment variables for database connections.

### `/frontend`
A modern React dashboard built using the Next.js framework. It acts as the primary user interface to monitor the rescue data and node statuses.
- `app/`: Next.js App Router directory containing pages, layouts, and React components.
- `public/`: Static assets for the Next.js application.
- `package.json` / `next.config.ts` / `tailwind.config` / `eslint.config`: Project configurations and dependencies.

### `/frontend-software`
An alternative or older iteration of the frontend application, seemingly built with Vite and React.
- `v1/`: Contains the Version 1 frontend project.
  - `src/`: React source code (e.g., `App.tsx`, `main.tsx`).
  - `index.html`: The HTML entry point.
  - `package.json`: Dependencies and Vite scripts.

### `/generated_configs`
Stores the C++ header files (`.h`) generated by the Python provisioning scripts.
- `node_a_config.h`, `node_b_config.h`, `rescue_config.h`: These files contain the hardcoded cryptographic keys (Ed25519, X25519 public/private keys) and node identities. They are meant to be included in the Arduino sketches before flashing the ESP32 devices to ensure an offline, secure deployment.

### `/hardware`
Contains the final, production-ready Arduino C++ code for the ESP32 devices.
- `mesh/`, `encrypted_mesh/`: Directories containing the `normal_node.ino` and `rescue_node.ino` sketches that define the hardware behavior.
- `test/`: Contains various testing sketches to validate hardware connections and basic mesh capabilities.
- `connections.md`: Documentation on how to wire the ESP32 devices (pins, sensors, etc.).

### `/keys`
Contains the Python provisioning scripts responsible for generating the offline cryptographic keys.
- `keys.py`: The Python script that generates the Ed25519 and X25519 key pairs for every node and builds the configurations placed in `/generated_configs`. This script is run exactly once before deploying the nodes.

### `/markle_path_test`
Contains testing scripts for the Merkle-set implementation.
- `merkle.py`: A Python implementation testing the logic for tracking nodes that have received a message, which prevents infinite broadcasting loops within the mesh network.

### `/ppt`
Contains architectural diagrams, flowcharts, and presentation images.
- Includes `.png`, `.jpeg`, and `.drawio` files demonstrating the hardware design, software architecture, and overall system flow visually.

### `/prototype`
Contains earlier iterations, proof-of-concepts, and experimental code.
- `attempt2/`, `attempt3/`, `final/`: Previous iterations of the hardware sketches.
- `prototype-backend/`: An older version of the server.
- `non_rescue_node/`, `rescue_node.ino`: Prototype Arduino sketches used before finalizing the architecture in the `/hardware` folder.

*Note: Each of these folders also contains its own `README.md` providing specific context regarding its internal workings.*
